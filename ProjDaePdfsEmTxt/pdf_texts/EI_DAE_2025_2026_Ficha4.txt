This error happens because the loading configuration for lists associated with entities is LAZY 
(fetch = FetchType.LAZY as a parameter of the @OneToMany and @ManyToMany annotations), 
so the subjects list is not loaded by default. To fix this, we have 3 options: 
(a) Explicitly force the loading of subjects using additional business. This will be our 
recommended solution for most scenarios.  
(b) Change the fetch parameter to FetchType.EAGER in the @ManyToMany relationship 
definition. This solution can only be used for one attribute per entity and may result in the 
“N + 1 select problem”.  
(c) Explicitly force the loading of subjects using a specific JPQL query with JOIN FETCH.  
Note that, while option (a) is good for most scenarios, the best option for your application will 
depend on your specific needs, e.g.: the complexity of the SQL queries, the amount of data being 
retrieved and how often the list is accessed. 
21. Implement option (a) by adding a new method  findWithSubjects() to StudentBean 
containing the following code: 
public Student findWithSubjects(String username){ 
    var student = this.find(username); 
    Hibernate.initialize(student.getSubjects()); 
    return student; 
} 
The code in bold will force the loading of the subject list for the given student.
